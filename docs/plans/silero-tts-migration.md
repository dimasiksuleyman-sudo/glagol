# План 0.4.0: удалить SaluteSpeech и добавить необязательную Silero TTS v5.5

Статус на 2026-09-12: реализация 0.4.0 и локальная сборка готовы. Предоставленная
пользователем настоящая модель проверена; pipeline заменён, SaluteSpeech удалён.
Программные проверки включают полную распаковку runtime кодом приложения,
синтез, отмену, миграцию и бэкап. Ручная проверка интерфейса, установки/обновления
и прослушивание остаются открытыми: помощник computer-use недоступен.
Далее сохранён исходный план; результаты исполнения — в
[журнале интеграции](../day-logs/day-2026-09-12-silero-integration-master-log.md).
Результаты и воспроизведение: [local-tts-runtime.ru.md](../local-tts-runtime.ru.md).
Согласованный продуктовый объём — из диалога
с пользователем 2026-09-12. Целевая платформа первого выпуска: Windows 10/11 x64.

## Результат для пользователя

Глагол остаётся приложением с двумя независимыми функциями: диктовкой и озвучкой.
Организация может установить приложение и пользоваться диктовкой, включая свой
офисный сервер, без Silero. Озвучка использует загружаемую Silero `v5_5_ru`
для некоммерческого использования. Интеграция SaluteSpeech полностью удаляется.

Следующий этап, отдельно согласованный пользователем: добавить **Yandex SpeechKit v3**
как провайдер озвучки для организаций и коммерческого использования. В объём 0.4.0
его реализация не входит. Перед тем этапом проверить актуальные условия, тарифы,
API и требования к передаче текста; этот план не утверждает их заранее.
Будущие ключи и настройки SpeechKit отделяются от настроек диктовки, а условия
Silero остаются привязаны только к Silero и не блокируют других TTS-провайдеров.

Основное приложение сохраняет MIT-лицензию. Для отдельно загружаемых компонентов
показываются их собственные лицензии. Silero не скачивается, не запускается и
не включается автоматически ни при установке, ни при обновлении, ни при запуске.
Отдельная загрузка не отменяет условий лицензии модели.

Ограничения Silero не распространяем на функции диктовки. Условия выбранного
STT-провайдера/модели продолжают действовать самостоятельно. GigaAM, её лицензия
и указание авторства остаются: удаляем именно интеграцию SaluteSpeech, а не все
упоминания Сбера независимо от контекста.

## 1. Проверить Silero на целевом ноутбуке и зафиксировать поставку

- В изолированном рабочем каталоге проверить официальную `v5_5_ru.pt` на CPU:
  пять голосов, русские предложения, вопросы, ударения, омографы, числа, даты,
  сокращения, латиница и фрагмент длинного документа.
- Машина: Ryzen 7 7730U, 8 ядер / 16 потоков, 16 ГБ RAM. Измерить холодный старт,
  тёплый синтез, отношение времени синтеза к длительности аудио, пиковую память
  и влияние синтеза на диктовку. Сравнить 2 и 4 потока, выбрать по измерениям.
- Основной путь: официальный PyTorch-пакет модели, отдельный скрытый рабочий
  процесс с переносимым Python и CPU PyTorch. Пользователю не нужны Python,
  pip, CUDA, права администратора или настройка PATH. Не использовать системный
  Python и не устанавливать пакеты через pip на пользовательской машине.
- Не делать системную регистрацию SAPI5 обязательной частью установки Глагола.
  SAPI5 пока не входит в этот план: у опубликованной сборки другой набор функций.
- Зафиксировать совместимые версии интерпретатора/PyTorch, размер каждого файла,
  SHA-256, лицензии и способ воспроизводимой упаковки рабочего процесса.
  Код адаптера написать самостоятельно; чужой NC-код не переносить в MIT-ядро.
- Определить постоянный источник загрузки runtime с версиями и хешами. Подготовка
  пакета входит в работу; публикация внешнего релиза — отдельное действие.
  Не выпускать приложение с несуществующими URL или непроверенным runtime.
- Размер модели около 145 МБ пока предварительный: точный размер с сервера
  не подтверждён. Модель и runtime показывать отдельно; измерить итоговую
  загрузку и место на диске, включая распаковку и временные файлы.

Критерий завершения: воспроизводимый локальный WAV от настоящей v5.5 на этой
машине; проверены все голоса и русский тестовый набор; собран рабочий комплект
без зависимости от установленного Python. Только после этого заменять pipeline.
Если официальный сервер недоступен, решать доступ к точному артефакту; другую
модель или непроверенную копию молча не подставлять.

## 2. Условия использования в трёх местах

Предлагаемый общий текст:

> Глагол можно использовать для диктовки, в том числе в организации.
> Озвучка Silero TTS v5.5 — дополнительный компонент под лицензией
> CC BY-NC-SA 4.0 для некоммерческого использования. Модель и движок
> скачиваются отдельно только по вашему выбору. Для диктовки Silero не нужна.

- В NSIS добавить информационный экран о независимых функциях и лицензиях.
  Главная лицензия приложения остаётся MIT; установка не требует согласия
  на использование Silero и не инициирует скачивание. Тихая установка также
  оставляет Silero выключенной, без автоматического подтверждения условий.
- В настройках перед первой загрузкой Silero показать краткое ограничение,
  авторство и полный текст лицензии; отдельное неподставленное подтверждение
  «Я ознакомился с условиями Silero и буду использовать её некоммерчески».
  Отказ/пропуск влияет только на озвучку, а не на установку и диктовку.
- Проверять наличие подтверждения и в Rust-командах загрузки/включения/синтеза,
  а не только в интерфейсе. Сохранять идентификатор модели и версию/хеш лицензии.
  Это уведомление и явный выбор пользователя, а не техническая проверка характера
  его деятельности. Не отправлять факт подтверждения на сервер.
- Условия доступны в интерфейсе и офлайн после установки; копия лицензии
  сохраняется рядом с моделью. При изменении условий запрашивать подтверждение
  заново. Подтверждение не переносится автоматически из бэкапа другого ПК.
- README RU/EN: заметный блок «Использование в организациях и лицензии».
  Добавить `docs/third-party/Silero-LICENSE.txt` и список лицензий runtime.
  Сохранить авторство и указание внесённых изменений, если они будут.
- Не объявлять весь Глагол некоммерческим и не перелицензировать веса под MIT.
  Не приписывать всему экспортированному аудио автоматически лицензию модели:
  условия модели описываем точно, права на исходные тексты — отдельно.

## 3. Менеджер необязательной озвучки и runtime

- Добавить отдельные `tts/silero` и `commands/tts`; состояние TTS независимо от
  `LocalModels` диктовки. Переиспользовать проверенные примитивы загрузчика
  (Range, отмена, размер, SHA-256, безопасная распаковка), сохранив существующие
  STT-команды и расположение скачанных GigaAM.
- Новый каталог через `paths.rs`: app-local `tts_models`, отдельный от
  `speech_models` и библиотеки `audio_cache`. Модель/runtime вне NSIS.
- Состояния: не установлена, скачивается, проверяется, готова, загружается
  в память, ошибка. Прогресс по файлам и суммарно; продолжение после обрыва,
  удаление частичных загрузок, повторная проверка/восстановление, удаление TTS.
- Зафиксированный HTTPS-каталог; проверка артефактов до выполнения, распаковка
  в staging, активация только после полной проверки, защита от выхода из каталога.
  `.pt` содержит исполняемый код: загружать только проверенный артефакт,
  не выполнять произвольные модели, пользовательские скрипты или torch.hub-код.
- Взаимодействие Rust с worker через ограниченный протокол stdin/stdout или
  локальный pipe, без открытого HTTP-порта. Запуск без консольного окна,
  таймаут, отмена, обработка падения, завершение вместе с приложением.
- Один синтез за раз; ограничение потоков и памяти, выгрузка по простою.
  Долгая озвучка не блокирует Tauri, интерфейс и горячую клавишу диктовки.
- После установки компонентов синтез полностью офлайн. В логах — версии,
  этапы, время, коды ошибок; текста, WAV и секретов в логах нет.

## 4. Заменить pipeline и интерфейс озвучки

- Ввести небольшой контракт TTS, отдельные настройки и ошибки. Заменить прямые
  `SaluteAuth`/`SynthesisClient` в `commands/synthesize.rs` на Silero backend.
  Контракт сразу отделяет общий pipeline от локальной модели и позволяет позже
  добавить Yandex SpeechKit v3: идентификатор провайдера, каталог голосов,
  возможности/лимиты, синтез фрагмента и общий формат результата/ошибок.
  Условия лицензии и готовность проверяются для выбранного провайдера.
  В 0.4.0 не добавлять неработающие пункты Yandex в UI, его SDK, ключи или запросы.
- Сохранить загрузку TXT/MD/DOCX/PDF, библиотеку, воспроизведение, экспорт WAV,
  прогресс и транзакционное сохранение. Аудио не пересекает frontend IPC.
- Пересмотреть `text/preprocessor.rs` и `text/chunker.rs`: лимит 3500/4000
  символов относится к SaluteSpeech. Для Silero определить безопасный размер
  по настоящей модели, делить по предложениям, корректно нормализовать числа,
  сокращения и латиницу, сохранять ударения и пунктуацию.
- Базовый выход — WAV PCM mono 24 кГц; другие частоты пока не выводить в UI.
  Проверить отсутствие потерь на стыках и единый формат всех фрагментов.
  Длинные документы обрабатывать последовательно с ограниченным буфером,
  не накапливая весь многочасовой WAV в памяти.
- Добавить отмену синтеза между фрагментами и при зависании worker; очистку
  временных файлов и отсутствие видимой «готовой» записи при ошибке.
- Заменить `CredentialsContext` состоянием готовности TTS. Убрать вызов
  `test_credentials` при старте приложения и блокировку по Сбер-ключу.
- Настройки: блок «Локальная озвучка — Silero v5.5», лицензия, загрузка,
  состояние, место на диске, удаление. На «Озвучить» — понятное предложение
  установить компонент, если его нет; не требовать установки для других страниц.
- Пять голосов из проверенной модели, выбор и короткое предпрослушивание после
  принятия условий. Сохранять выбранный голос. Пока модель не загружена,
  не выдавать кнопку синтеза за готовую к работе.
- Удалить бесплатную квоту и счётчик SaluteSpeech из `UsageSection`.
  Статистику минут диктовки сохранить; отдельный новый аналитический экран
  озвучки для этого перехода не нужен.

## 5. Удалить SaluteSpeech и обеспечить обновление данных

- Удалить `src-tauri/src/salute/`, `commands/credentials.rs`, их регистрацию
  и IPC-обёртки; убрать OAuth/token cache и TLS-клиент SaluteSpeech из AppState.
  Обновить вызовы конструктора и тесты, которые собирают AppState.
- Удалить сертификат `russiantrustedca.pem`, разрешения/домены SaluteSpeech
  в CSP, описания пакета/установщика и зависимости, используемые только ими.
  `reqwest`, keyring и ключи облачной/офисной диктовки остаются необходимыми.
- Для обновления оставить узкую идемпотентную процедуру удаления только
  `Glagol/salutespeech_auth_key`. NotFound — успех; ошибка OS-хранилища
  не блокирует запуск, фиксируется без содержимого ключа и может повториться.
  Ни один ключ диктовки эта процедура не читает и не удаляет.
- Старые документы, WAV, позиции прослушивания и метаданные голосов сохраняются.
  Старые ID голосов отображаются через legacy-label/fallback без зависимости
  от живого провайдера. Записи не помечаются задним числом как Silero.
  Для новых записей хранить провайдера и ID голоса раздельно, чтобы будущий
  SpeechKit не смешивал свои голоса с Silero. При добавлении поля провайдера
  использовать новую миграцию, старые записи обозначить как legacy SaluteSpeech.
- Сохранить таблицу `api_usage`: в ней находятся и минуты диктовки.
  Прежние миграции не переписывать. Новые поля/миграции добавлять только по
  реальной необходимости, сохранять совместимость чтения существующих данных.
- Проверить восстановление старого бэкапа. Веса и runtime не входят в бэкап
  библиотеки; восстановление не включает TTS и не принимает лицензию за пользователя.
- Текущие руководства, README RU/EN, SECURITY, PROJECT_STRUCTURE, CLAUDE,
  CONTRIBUTING, шаблоны GitHub и метаданные очищаются от действующих инструкций
  SaluteSpeech. Старые записи CHANGELOG и архивные day-logs сохраняют историю.
  В новой секции CHANGELOG явно описать удаление провайдера и переход на Silero.

## 6. Проверка и поставка

| Сценарий | Условие готовности |
|---|---|
| Чистая установка без Silero | Диктовка и офисный сервер доступны; нет требований Сбер-ключа, TTS-download или подтверждения NC |
| Интерактивная и тихая установка | Лицензионное уведомление доступно; TTS по умолчанию выключена, согласие не выставляется автоматически |
| Загрузка Silero | Отмена, продолжение, неверный хеш, нехватка места, недоступный сервер, повреждённый runtime обработаны |
| Прямые IPC-вызовы | Без подтверждения условий TTS не скачивается и не запускается |
| Реальный синтез | Все пять голосов, русский тестовый набор, длинный документ, корректный WAV и границы фрагментов |
| Повторный запуск без интернета | Установленная и включённая Silero озвучивает; runtime не требует скачивания вспомогательных файлов |
| Одновременная диктовка и озвучка | Хоткей, готовность микрофона, полоски уровня и вставка текста работают |
| Удаление/отключение Silero | Диктовка работает; пользовательская библиотека и GigaAM остаются |
| Обновление с 0.3.0 и старый бэкап | Документы, WAV, настройки и ключи STT сохранены; старый Сбер-ключ удаляется адресно |
| Отсутствие SaluteSpeech | Нет production-клиента, авторизации и запросов к его доменам; допустимы только миграционная очистка, legacy-метаданные и история |
| Windows-ярлыки | Иконка Глагола корректна после новой установки и обновления; проверить исправление кэша ярлыка в установщике |

Автотесты: новое поведение загрузки/согласия/worker и миграции; сохранить
существенные проверки библиотеки, диктовки, WAV и парсеров. Тесты удалённого
провайдера удалить вместе с ним, не имитировать их успех заглушками.
Прогнать fmt, clippy, cargo test, TypeScript/build, проверку версий и NSIS.
Выполнить реальный smoke test Silero на целевой машине, ручную проверку UI,
чистой установки и обновления; в отчёте отделить выполненное от непроверенного.

Целевая версия — 0.4.0 во всех четырёх местах, с автоматической проверкой.
Работу вести в отдельной ветке `codex/silero-tts`; логичные локальные коммиты:
проверенный runtime/загрузка; новый pipeline и UI; удаление SaluteSpeech и
совместимость; документация/лицензии/установщик. Каждый коммит оставляет проект
собираемым. PR и push без отдельного поручения не делать.
