# Локальная озвучка Silero в Глаголе 0.4.0

[English](local-tts-runtime.md)

Реализована в исходниках 0.4.0; установщик Windows NSIS собран локально.
План перехода: [silero-tts-migration.md](plans/silero-tts-migration.md).
Yandex SpeechKit v3 для коммерческой озвучки — следующий отдельный этап.
Диктовка, включая GigaAM и офисный сервер, независима от этой работы.

## Проверено 2026-09-12

На Windows x64, Ryzen 7 7730U / 16 ГБ RAM собран переносимый runtime:

- Python 3.11.9 embedded и PyTorch 2.7.1+cpu; системный Python, pip и CUDA не нужны.
- Все 13 архивов проверены по размерам и SHA-256 до распаковки.
- Загрузка движка: **249 346 278 байт**. Модель: **145 420 684 байта**.
  Вместе: **394 766 962 байта** (~395 МБ); около 1,9 ГБ на диске с сохранёнными
  архивами. Веса и Python/PyTorch не входят в NSIS.
- Распаковка: **1 319 448 970 байт**, 14 483 файла, без JSON-описи.
  Это полная распаковка, включая SDK-файлы PyTorch; уменьшение ещё не проверено.
- Из изолированного интерпретатора успешно импортированы torch, numpy,
  num2words и docopt; проверены CPU-тензор и преобразование русского числа.
- Четыре теста сборщика прошли: выход из каталога, повреждение артефакта,
  очистка неудачной распаковки с сохранением соседних файлов, активация/опись.
- Проба модели отвергает неверный SHA-256 до импорта PyTorch и создания WAV.

Предоставленный пользователем `v5_5_ru.pt` совпал с закреплённым SHA-256 ниже.
Настоящая модель создала валидные WAV для всех пяти голосов: 32 проверки на двух
и четырёх потоках CPU. На двух потоках загрузка Python/torch/модели заняла 3,25 с
(без проверки целостности runtime приложением). Первый синтез: 1,48 с на 5,15 с
аудио; прогретая Xenia: 0,27 с на 4,53 с; длинный абзац: 1,81 с на 22,39 с.
Пиковый working set процесса — около 752 МБ. Четыре потока дали небольшой выигрыш,
поэтому выбраны два. Это замеры на данном ноутбуке, а не минимальные требования.

GigaAM CTC распознала один публичный WAV примерно за 0,30 с отдельно и 0,40 с
при одновременной озвучке с одинаковым текстом. Это проверка совместной работы
движков, а не готовности живого микрофона. Числа и Windows/USB из WAV нового
адаптера также прошли проверку распознаванием. Грамматика чисел/дат и чтение
латиницы остаются эвристическими; валидный звук и ASR не заменяют прослушивания.

Нативный тест в release-режиме распаковал все архивы кодом Rust приложения,
сверил встроенную опись, озвучил документ из нескольких фрагментов в библиотеку
и отменил активный синтез. Тесты миграции и бэкапа проверяют сохранение старых
документов и исключение компонентов, согласия Silero и образцов голосов из бэкапа.
Визуальная проверка UI, чистая установка/обновление и прослушивание остаются
ручными: помощник computer-use был недоступен во время реализации.

Сервер модели не отвечал из командной строки разработчика. В настройках есть
автоматическая загрузка и импорт точного проверенного файла, скачанного браузером;
произвольный `.pt` отклоняется. Движок скачивается из проверенных источников ниже.
Это не заявление об устранении сетевой проблемы.

Официальный SAPI-установщик с GitHub изучен без запуска/установки: в нём
`v5_5_ts.bin` и отдельные модули, а не `v5_5_ru.pt`. Он не используется как
подмена. PyTorch 2.8.0+cpu тоже запускался, но его Windows-архив весит
619 392 861 байт, поэтому в подготовительный каталог выбран 2.7.1+cpu.

## Поведение приложения

Настройки требуют явного подтверждения некоммерческого использования, связанного
с моделью и хешем лицензии, перед установкой/импортом. Rust повторно проверяет его
перед загрузкой модели и синтезом. Установщик показывает информационное сообщение,
не включая Silero. Подтверждение хранится в `tts_models/acknowledgement.json` и не
попадает в бэкап. Диктовка, воспроизведение/экспорт библиотеки и импорт файлов
от него не зависят.

Артефакты скачиваются с прогрессом, отменой, продолжением и проверкой SHA-256.
Безопасная распаковка активируется только после сверки всех ожидаемых файлов со
встроенной описью. Приложение запускает переносимый интерпретатор с изоляцией
Python-путей, без pip, hub, регистрации SAPI и сетевых вызовов при синтезе.
Обмен — ограниченные JSON-метаданные и приватные WAV; аудио не передаётся по IPC.
Это управление дочерним процессом и изоляция Python-путей, а не песочница ОС.
Процесс завершается с родителем, при отмене/ошибке или через три минуты простоя.

Фрагменты озвучиваются последовательно, WAV записывается постепенно. Ошибка или
отмена не создаёт успешную запись библиотеки. Старые WAV/голоса доступны с
провайдером `salutespeech-legacy`, новые документы используют `silero`. Удалены
OAuth, API/TLS-материалы SaluteSpeech и интерфейс квот озвучки. Однократно удаляется
только прежний ключ TTS; профили, ключи и статистика диктовки независимы.

## Воспроизведение разработчиком

Эти инструменты не вызываются установленным Глаголом. Все файлы хранить в
`.scratch`; не добавлять веса/интерпретатор в Git или NSIS.

```powershell
node scripts/silero/download.mjs .scratch/silero/downloads
# download.mjs уже проверил SHA-256 архива Python.
Expand-Archive .scratch/silero/downloads/python-3.11.9-embed-amd64.zip .scratch/silero/bootstrap-python
& .scratch/silero/bootstrap-python/python.exe -I -B scripts/silero/assemble.py --downloads .scratch/silero/downloads --destination .scratch/silero/runtime-271
& .scratch/silero/runtime-271/python.exe -I -B scripts/silero/test_assemble.py
```

Каталог назначения должен быть новым: существующий runtime сборщик не
перезаписывает. Распаковка идёт в соседний `.staging`, ссылки и опасные пути
отвергаются, активация происходит после завершения. `python311._pth` отключает
пользовательские site-packages и переменные Python-путей. `setup.py` не выполняется.

Запустить `probe.py` из этого runtime с
`--model <полный путь к v5_5_ru.pt> --output <новый каталог> --threads 2`,
потом повторить с 4 потоками в другом процессе/каталоге. Ограничить процесс
таймаутом снаружи. Проба пишет WAV PCM mono 24 кГц и `report.json` с временем,
RTF и пиковым working set. Она использует только публичные тестовые фразы.
Прослушать WAV: техническая валидность не подтверждает качество произношения.

Тесты адаптера: `python.exe -I -B scripts/silero/test_worker.py`.
После осознанного обновления и проверки runtime пересоздать каталог и опись Rust:
`node scripts/silero/generate-catalog.mjs <runtime.json>`.
Для нативного smoke-теста подготовить отдельный `GLAGOL_TTS_SMOKE_ROOT` с моделью
и всеми 13 архивами в корне, задать `GLAGOL_TTS_ASSEMBLE_SMOKE=1` и выполнить
`cargo test --release --manifest-path src-tauri/Cargo.toml native_silero_pipeline_and_cancel -- --ignored --nocapture`.
Если загрузка Pdfium при сборке недоступна, задать `PDFIUM_LIBRARY_PATH` полным
путём к локальному `src-tauri/resources/pdfium.dll`. Не направлять smoke-тесты
на пользовательские данные.
