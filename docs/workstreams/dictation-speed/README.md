# Скорость диктовки и отключение озвучки (0.6.2)

Цель: найти причину долгого локального распознавания на ПК пользователя (на
ноутбуке распознаёт быстро) и дать возможность выключить озвучку, если она не
нужна, чтобы не ждать её подготовки.
Основание: сообщение пользователя 2026-11-09 — «Очень долгое распознавание на
локальной модели на ПК. На ноутбуке распознаёт быстро. Надо включить
расширенное логирование и найти, в чём проблема, если она есть. Дать
возможность отключать озвучку…».

В scope: диагностические записи журнала без текста, аудио и ключей, в том
числе для пропадающего индикатора диктовки (GL-006, запрос пользователя
2026-11-09: «постоянно пропадает пилюля… надо в логах выяснить почему»); переключатель
«Подробный журнал» и кнопка открытия папки журналов; настройка «Озвучка
включена»; оба руководства, README, CHANGELOG. После сбора журналов на обеих
машинах — анализ и отдельное согласованное исправление причины.
Вне scope до анализа журналов: смена модели/движка, GPU-ускорение, исправление
GL-006, подпись Authenticode. Проверка на ПК — до выпуска 0.6.2.

Решения:
- Сначала измерения, потом исправление: гипотезы (выбор CPU-варианта ggml,
  число потоков, фоновое ограничение Windows для скрытого окна, конкуренция
  с прогревом Silero, полная проверка файлов при первой загрузке) не чинятся
  вслепую.
- Логи движка transcribe.cpp остаются выключенными (могут содержать текст);
  бэкенд, устройства и тайминги берутся через его публичный C API.
- Короткие тайминговые строки пишутся всегда (одна на диктовку, только числа);
  «Подробный журнал» дополнительно поднимает уровень всего приложения до debug.
- Выключенная озвучка не запускает проверку файлов Silero при старте, прогрев
  worker и синтез; уже работающий worker завершается. Библиотека и плеер
  остаются. Модели и согласие не удаляются.

Критерии: гейты; на ПК и ноутбуке собраны журналы с одинаковой фразой;
причина названа по данным журнала или явно отмечена unknown.
