### F1. Вставка в главном окне

- По журналу 0.7.0 оба события Ctrl+Win дошли. Отпускание модификаторов
  подтверждено в момент проверки. Строка «paste modifier state before
  dispatch» стоит перед SendInput. Она сама по себе не подтверждает
  приём Ctrl+V WebView2. Даже полный результат SendInput подтверждает
  постановку событий во входную очередь, а не исполнение команды в поле.
- VK 0xE8 — отдельная маска меню «Пуск». Она отправляется при удерживаемом
  Win и игнорируется нашим хуком как синтетическое событие. Win и маска
  меняют последовательность ввода по сравнению с основным хоткеем, поэтому
  их обработка оболочкой и WebView2 остаётся гипотезой. Лог не показывает
  состояние ввода на стороне WebView2, точная причина не установлена.
  [SendInput](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput).
- Оба хоткея используют снимок окна из GL-014. Для своего процесса проверяются
  исходное и текущее окно, а событие с текстом получает только главный
  WebView. Подтверждение содержит идентификатор и флаг результата. Поле
  заменяет выделение или вставляет у курсора и отправляет input для React.
  Если поле недоступно, окно сменилось или WebView не ответил, остаётся
  буфер. После истечения срока WebView игнорирует запрос. Буфер при
  успешной вставке не меняется. В журнале только статус доставки и время.

### F2. Импорт PDF

- Вместо итератора, который завершался при первой ошибке загрузки страницы,
  перебираются индексы страниц. Ошибки загрузки и создания текстового слоя
  считаются отдельно от пустых страниц. Доступный текст импортируется по
  порядку. Если ни одна страница не дала текст, прежний редактор сохраняется.
- Ошибка пароля определяется по коду Pdfium и локализуется без технических
  деталей. Смешанный PDF показывает число страниц без текста и число
  пропусков. Для полностью пустого текстового слоя сохраняется подсказка OCR.
  Предупреждение о шрифте появляется, если на хотя бы одной странице больше
  20% непробельных символов — U+FFFD или символы Private Use Area. Текст
  доступен для просмотра, порог относится только к предупреждению.
- Параллельный прогон новых тестов прерывался в Pdfium с ошибкой памяти.
  Те же тесты проходили по одному. Доступ к общей библиотеке сериализован
  на время жизни документа. Сходство сбоя с причиной у пользователя пока
  не подтверждено. Отдельная попытка сборки закончилась нехваткой места
  в каталоге артефактов. Очистили устаревшие артефакты сборки и запустили
  проверки повторно.
- PDF для проверок собираются в тестах. Есть документ с двумя читаемыми
  страницами вокруг отсутствующего объекта и пустой страницы, полностью
  пустой и полностью нечитаемый документы, карта шрифта с PUA и PDF
  с паролем. Известный пароль в тесте проверяет корректность синтетического
  файла. Лимиты импорта остались 10 МБ и 500 000 символов.

### F3. Ручная проверка пользователем

1. Установить тестовую сборку на Windows. В настройках включить автоматическую
   вставку и Ctrl+Win. На экране «Озвучить» поставить курсор в середину
   тестового текста, затем выделить несколько символов. Продиктовать
   по Ctrl+Win и основному хоткею. Текст должен вставиться один раз,
   на месте курсора или выделения. До начала можно скопировать контрольное
   слово и убедиться, что при успешной вставке оно осталось в буфере.
2. Снять фокус с редактора или сменить окно до конца распознавания. Текст
   должен быть доступен в буфере. Проверить режим «Только буфер обмена»
   и обычную автовставку обоими хоткеями в Блокнот.
3. В «Озвучить» открыть обычный PDF и PDF со смесью текста и пустых/сканированных
   страниц. В редакторе должен остаться читаемый текст, а сообщение должно
   показать число страниц без текста. Для повреждённой страницы сверить
   число пропусков и наличие следующих читаемых страниц. Полный скан открывает
   подсказку OCR и сохраняет прежний текст редактора.
4. Открыть PDF с паролем и проверить «Файл защищён паролем» в RU и
   «The file is password protected» в EN. Если снова встретится файл с
   «кракозябрами», проверить наличие предупреждения о шрифте. При отклонении
   сообщить точное сообщение приложения и тип файла без текста документа.

Ручная проверка Windows/WebView2 и исходные PDF пользователя ожидаются.
