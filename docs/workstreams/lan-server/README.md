# Глагол как сервер распознавания в локальной сети

Цель: Глагол на одной машине (например, ПК с видеокартой) принимает записи от
Глаголов на других компьютерах сети и возвращает текст, чтобы слабым машинам
не нужна была своя локальная модель.
Основание: вопрос пользователя 2026-11-13 — «Чтобы глагол поставить и работать
как сервер, можно его просто установить на ноутбук?»; ответ — нет, Глагол сейчас
только клиент. Пользователь: «Запиши в туду, но делать не будем. Пока.»

Сейчас (0.6.6): режим «Сервер организации» — клиент OpenAI-совместимого
`/audio/transcriptions` (whisper.cpp server, faster-whisper-server/speaches и
т. п.), сервер ставит администратор. HTTP разрешён только для localhost/частных
IP; звуки-заминки чистит клиент после ответа.

Направление (согласовать перед началом):
- тот же OpenAI-совместимый протокол, чтобы существующий клиентский режим
  работал без изменений; движок — уже установленные GigaAM/Moonshine;
- выключено по умолчанию, явное включение, выбор порта, слушать только
  локальную сеть; ключ доступа (Bearer) хранится в keyring, не в SQLite/env;
- шифрование: решить в L1 (самоподписанный сертификат с закреплением на
  клиенте или явное предупреждение о HTTP в доверенной сети);
- очередь и лимиты: одна операция распознавания за раз, размер и длительность
  записи ограничены, без журналирования речи и текста;
- брандмауэр Windows: понятное сообщение, без тихих изменений правил;
- CLAUDE.md: проверить инварианты сети/безопасности, при необходимости
  дополнить решением в L1.
Риски: открытый порт на машине пользователя, нагрузка на ПК во время его же
диктовки, совместимость клиентов.
Вне scope: доступ из интернета, учётные записи, TTS по сети.
