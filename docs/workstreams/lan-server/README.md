# Сервер распознавания внутри Глагола (офис в локальной сети)

> План реализации, согласованный с пользователем 2026-11-19. Заменяет черновое
> направление от 2026-11-13. Журнал серии — [log.md](log.md); очередь —
> [roadmap](../../roadmap.md).

## Context

Пользователь 2026-11-19 выбрал «фишку» для продвижения: Глагол на одном мощном
компьютере раздаёт русское распознавание (GigaAM) офисным компьютерам в сети.
Поиск показал близкий аналог (OpenWhisper «shared engines over LAN»), но не
офисного решения «один сервер, много сотрудников, ключ доступа» и ничего с
сильным русским офлайн. Приоритет — российская часть: речь не покидает офис
(аргумент для компаний с персональными данными), сильный русский без облака,
слабые ПК получают быстрое распознавание. Пользователь: «сначала сделаем, а я
потом поставлю пробу на сына, на комп, у него 1060 с 6 гигами» и «составь план
реализации, код, удобство настроек… и положи его в репо».

Решения (AskUserQuestion, 2026-11-19):
- языки v1: **только русский** (GigaAM); английский (Moonshine умеет лишь
  поток с микрофона) — отдельным шагом позже;
- подключение: **код подключения** (адрес + ключ одной строкой: «Скопировать»
  на сервере → «Вставить код» на клиенте) **+ «Найти Глагол в сети»** (поиск —
  последним шагом);
- **ключ доступа всегда нужен** (Глагол создаёт его сам и кладёт в код).

Что уже есть и переиспользуется:
- клиент: режим «Сервер организации» — `stt/openai_compat.rs`
  (`POST {base}/audio/transcriptions` multipart: file=WAV 16 кГц моно s16,
  model, language, response_format=json; `GET {base}/models` как проверка;
  `Authorization: Bearer`), ключ в keyring, HTTP разрешён только для
  частных IP/localhost (`commands/speech.rs::validate_server_url`);
- движок: `LocalModels::recognize(id, &pcm)` (`stt/local/mod.rs`) — сам
  ждёт блокировку движка (очередь), учитывает видеокарту/потоки хоста;
  выбранная русская модель — `stt_local_model_ru`;
- `dictation/resample.rs::resample_to_16k`, `hound` для WAV;
- hyper 1.9 / hyper-util 0.1.20 / http-body-util уже в Cargo.lock (через
  reqwest) — сервер без новых крейтов, только включить features.

## Шаги (L1–L6)

### L1. План в репо (этот шаг)
`docs/workstreams/lan-server/README.md` — план целиком (архитектура, API,
безопасность, удобство, этапы, риски); state.json: шаги L1–L6, серия active,
L1 done; `docs/roadmap.md` — сервер первым в очереди; log.md.

### L2. Ядро сервера (Rust), без UI
Новый модуль `src-tauri/src/lan_server/`:
- `mod.rs` — `start(config, recognizer) -> Handle`, `stop()`, статус
  (адрес, порт, запросов/ошибок, активные клиенты за 10 мин — только счётчики
  в памяти, IP не пишутся в журнал и на диск);
- `http.rs` — hyper 1.x (`http1`, `server`), tokio; маршруты:
  - `POST /v1/audio/transcriptions` → `{"text": "..."}` (`response_format`
    `json`/`text`); `language` ∈ {ru, отсутствует, auto} → русский, иначе
    400 «served language: ru»; `model`/`prompt` принимаются и игнорируются;
  - `GET /v1/models` → `{"object":"list","data":[{"id":"<модель>"}]}`;
  - `GET /` → короткий статус «Glagol server» (для проверки в браузере);
- `multipart.rs` — свой ограниченный парсер multipart/form-data (тело ≤ 25 МБ,
  поля ≤ 4 КБ, ровно один file), тесты на испорченные входы;
- `audio.rs` — WAV PCM 16-бит любая частота/каналы → моно 16 кГц
  (`resample_to_16k`), ≤ 10 мин; иное → 415 с понятным текстом;
- `auth.rs` — ключ 32 случайных байта (base64url), хранится в keyring
  (`Glagol/lan_server_key`), сравнение за постоянное время; нет/неверный → 401;
- сеть: слушать `0.0.0.0:<порт>` (по умолчанию 8765), принимать только
  loopback/частные IPv4 (10/8, 172.16/12, 192.168/16), CGNAT 100.64/10
  (Tailscale), link-local, IPv6 ULA/loopback; остальным — закрыть соединение;
- лимиты: очередь ≤ 32 запросов (иначе 429 + `Retry-After: 2`; клиенты Глагола повторяют до 3 раз; было ≤ 9 до замера 2026-11-19),
  таймаут запроса 120 с, одновременно ≤ 32 соединений; распознавание через
  трейт `Recognizer` (реальный — `LocalModels` + `spawn_blocking`; тестовый —
  фейк);
- журнал: только числа (длительность аудио, ожидание в очереди, время
  распознавания, код ответа) — никакого текста/аудио/ключей/IP;
- тесты: модульные (multipart, auth, фильтр IP, аудио) + интеграционный —
  поднять сервер на 127.0.0.1:0 с фейковым распознавателем и вызвать его
  **существующим клиентом** `OpenAiCompatStt` (transcribe + list_models,
  401 без ключа, 429 при переполнении) — доказывает совместимость.
- `Cargo.toml`: прямые зависимости `hyper = { version = "=1.9.0", features
  = ["http1","server"] }`, `hyper-util` (`server`, `tokio`, `http1`),
  `http-body-util` — те же версии, что в lock; `rand`/`getrandom` уже есть?
  (проверить; иначе ключ из `uuid` v4 ×2).

### L3. Хост: настройки и интерфейс
- ключи `lan_server_enabled` (false), `lan_server_port` (8765),
  `lan_server_keep_awake` (true); применение сразу и при запуске (`lib.rs`);
- «Настройки» → «Диктовка» → новый блок «Сервер для других компьютеров»
  (свёрнут, как «Управление моделями»):
  - переключатель «Раздавать распознавание по сети»;
  - строка статуса: «Работает · 192.168.1.10:8765 · GigaAM CTC · видеокарта ·
    сегодня 37 запросов, сейчас подключено 3» / ошибки простыми словами
    («Русская модель не установлена», «Порт занят», «Брандмауэр…»);
  - **код подключения** (`glagol://192.168.1.10:8765/?key=…`) + «Скопировать»;
    «Показать ключ», «Создать новый ключ» (старые клиенты отключатся —
    предупреждение);
  - «Дополнительно»: порт; «Не давать компьютеру засыпать, пока сервер
    включён» (Windows `SetThreadExecutionState`, по умолчанию вкл.);
- адрес в сети: определить основной IPv4 (UDP-«connect» без отправки
  пакетов) + список всех частных адресов;
- брандмауэр Windows: при первом запуске Windows спросит разрешение — в
  интерфейсе и руководстве объяснить «Разрешить в частных сетях»; если
  клиенты не подключаются — кнопка «Как открыть порт» с командой
  `New-NetFirewallRule` для PowerShell (от администратора), без тихих
  изменений правил.

### L4. Клиент: подключение в одно действие
- в «Сервер организации» кнопка «Вставить код подключения»: разбирает
  `glagol://host:port/?key=…` → `base_url = http://host:port/v1`, модель
  с сервера (`GET /v1/models`), язык ru, ключ в keyring; сразу «Проверить»
  (существующий `list_models`-зонд) и показать «Подключено к Глаголу на
  192.168.1.10 · GigaAM CTC»;
- чистка звуков-заминок и вставка работают на клиенте как обычно.

### L5. «Найти Глагол в сети»
- сервер отвечает на UDP-широковещательный запрос (порт 8766) в локальной
  сети: `{"glagol":1,"name":"<имя ПК>","port":8765,"model":"…"}` — без ключа;
- клиент: кнопка «Найти» шлёт broadcast, 1,5 с собирает ответы, показывает
  список «Имя ПК · адрес · модель»; выбор подставляет адрес, остаётся ввести
  ключ (или вставить код). Ответ только частным адресам.

### L6. Замер и проверка на двух машинах
- `scripts/lan-server-bench.mjs` (Node, без зависимостей): N параллельных
  клиентов шлют WAV-образец по коду подключения, печатают задержки
  (медиана/95%) и пропускную способность;
- вручную: ПК сына (GTX 1060 6 ГБ, Vulkan) — сервер; ПК пользователя и
  ноутбук — клиенты; диктовка с обоих, 401 с неверным ключом, переподключение
  после сна, брандмауэр; цифры — в журнал и для продвижения.

Документы на каждом шаге: USER_GUIDE RU/EN (новый раздел «Сервер для других
компьютеров»), README обе части (фишка), CHANGELOG, SECURITY.md (открытый
порт, ключ, HTTP без шифрования в частной сети, что пишется в журнал),
CLAUDE.md (инвариант: сервер выключен по умолчанию, только частные сети,
ключ обязателен, без журналирования речи/текста/IP), PROJECT_STRUCTURE.md.

Вне первой версии: английский (Moonshine из WAV), TLS с закреплением
сертификата, доступ из интернета, учётные записи, очередь с приоритетами.
