В GlagolQA открыть PowerShell и выполнить команду ниже. Она создаёт на
рабочем столе UTF-8 файл qa-silero-long.txt с 30 нумерованными абзацами
синтетического текста. CreateNew защищает существующий файл от перезаписи.
Ожидается «Готово» и файл на рабочем столе. При совпадении — «Го».
Загрузка файла и синтез будут следующим отдельным пунктом.

~~~powershell
$qaText = (1..30 | ForEach-Object { "Абзац $_. Мы проверяем озвучку длинного документа. За окном начинается новый день. На улице слышны голоса людей и шум проезжающих машин. В комнате тихо, на столе лежит открытая книга. Каждая фраза должна прозвучать полностью и в правильном порядке. Конец абзаца $_." }) -join ([Environment]::NewLine + [Environment]::NewLine)
$qaPath = Join-Path ([Environment]::GetFolderPath('Desktop')) 'qa-silero-long.txt'
$qaFile = [IO.File]::Open($qaPath, [IO.FileMode]::CreateNew)
try { $qaBytes = [Text.Encoding]::UTF8.GetBytes($qaText); $qaFile.Write($qaBytes, 0, $qaBytes.Length) } finally { $qaFile.Dispose() }
Write-Output 'Готово'
~~~

## Порядок продолжения

Выдавать ровно одну проверку с ожидаемым результатом за раз; следующий пункт
только после ответа и записи результата текущего. С T22 пользователь изменил
протокол: скриншоты не обязательны; «Го» означает, что он выполнил текущую проверку
и получил именно описанный ожидаемый результат. В таком случае записывать manual
PASS с источником «подтверждение пользователя по согласованному протоколу».
Это не подтверждение будущих проверок. При отклонении пользователь описывает его;
при неясном ответе уточнить результат. Скриншоты сохранять, если пользователь их
присылает, но не запрашивать их по умолчанию.
Сначала установить параметры и исходное состояние второго ПК, затем передавать
тестовый комплект. Чистую установку и обновление проверять на отдельных чистых
профилях/состояниях; существующие данные сначала выявить и сохранить.
Полный охват установки: [installation.md](installation.md); последующие проверки
Silero и диктовки — V3/V4. Подготовка среды не закрывает installation.
