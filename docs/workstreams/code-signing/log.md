## 2026-11-20T22:40:05.763Z — C1, проверка первоисточников

- **Условия OSS.** Бесплатная программа требует OSI-лицензию для всех
  компонентов без двойной коммерческой лицензии, отсутствие проприетарного
  кода с оговоркой о системных библиотеках, активную поддержку и уже выпущенный
  артефакт нужного формата. Страница загрузки должна описывать программу.
  Foundation разрешает включать сторонние OSS-библиотеки в установщик, а
  подпись запрашивается для собственных сборок из своего репозитория.
  Foundation проверяет репутацию и контроль над кодом при приёме.
  Отдельно скачиваемые веса Silero под CC BY-NC-SA 4.0 раскрыты в черновике.
  Их допустимость для участия Глагола должен подтвердить Foundation.
  [Условия Foundation](https://signpath.org/terms.html).
- **Политика и роли.** Условия требуют раздел или ссылку «Code signing policy»
  на главной странице и страницах скачивания/выпусков, дословную атрибуцию,
  имена ответственных и описание конфиденциальности с учётом сторонних сервисов.
  Для всех участников нужна MFA в SignPath и в системе управления кодом.
  Каждому выпуску требуется ручное одобрение. Для подписываемых бинарников
  SignPath требует ограничения на метаданные имени и версии продукта.
  Подготовлена политика RU/EN в главном README. Практическая настройка MFA
  и ограничений метаданных остаётся за сопровождающим и C3.
  [Условия Foundation](https://signpath.org/terms.html#conditions-for-free-code-signing-certificates-from-signpath-foundation).
- **Подача.** На официальной странице Apply опубликована форма. Поля
  проверены по конфигурации встроенной формы без отправки данных.
  Среди обязательных полей есть Reputation и Build System с вариантом
  GitHub Actions. Форма предусматривает email для уведомлений и подтверждение
  отправки. Подготовлены ответы по её полям и пояснения для переписки.
  В условиях и форме не найдено подтверждения срока «около недели» или
  доступности для конкретной страны. Foundation сообщает, что личная
  идентификация получателя сертификата не нужна, но форма просит имя и email
  для учётной записи. Решение по заявке принимает Foundation.
  [Форма Apply](https://signpath.org/apply) · [Описание программы](https://signpath.org/) ·
  [Встроенная форма, определение полей](https://forms-eu1.hsforms.com/embed/v4/render-definition/145110231/bf62807d-bb72-4e45-9bde-1f3a53ba2472).
- **Происхождение и область подписи.** Документация подтверждает проверку
  происхождения артефакта из GitHub Actions. На 20 ноября GitHub показывал
  публичный MIT-репозиторий, v0.6.6 как latest и 48 загрузок NSIS EXE в 12
  стабильных релизах (4 для v0.6.6). Счётчики не измеряют уникальных пользователей.
  Текущий CI собирает NSIS для проверки, а опубликованный установщик
  собирается у сопровождающего. Перенос сборки выпуска и загрузка артефакта
  остаются за C2. Выбран заявочный объём — внешний EXE установщика. В
  справочнике PE поддерживает Authenticode, но не вложенные файлы. Поддержка
  отдельной подписи glagol.exe до сборки NSIS для этого OSS-проекта не подтверждена.
  [Релизы](https://github.com/dimasiksuleyman-sudo/glagol/releases) ·
  [Windows CI](../../../.github/workflows/ci.yml) ·
  [GitHub Actions в SignPath](https://docs.signpath.io/trusted-build-systems/github) ·
  [Форматы артефактов](https://docs.signpath.io/artifact-configuration/reference).
- **Метка времени и обновления.** Для файловой подписи SignPath автоматически
  управляет метками времени. Конкретная TSA и формат метки для NSIS Глагола
  ещё не проверены. В C3 получить окончательный EXE после Authenticode и
  timestamp, подписать эти байты существующим ключом обновлений Tauri, затем
  подготовить latest.json и SHA256SUMS. В C4 проверить обе подписи и обновление.
  Реальную подпись, метку времени, обновление и поведение SmartScreen в C1
  не проверяли.
  [Метка времени в SignPath](https://docs.signpath.io/crypto-providers/#timestamps) ·
  [Подпись обновлений Tauri](https://v2.tauri.app/plugin/updater/#signing-updates) ·
  [Ранбук выпуска](../../runbooks/release.md).
