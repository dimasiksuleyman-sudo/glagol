# Подпись установщика Windows (Authenticode)

Цель: убрать «Windows защитила ваш компьютер» (SmartScreen) и «Неизвестный
издатель» при установке Глагола — заметный барьер для новых пользователей.
Основание: пользователь 2026-11-19 попросил промпт для побочного исследования
«самый быстрый путь к бесплатному сертификату» и принёс результат; задача
четвёртая в [очереди](../../roadmap.md).

## Итоги исследования (по данным побочного чата, не перепроверено)

| Вариант | Цена | Для частного лица из РФ | Заметки |
|---|---|---|---|
| SignPath Foundation | бесплатно для OSS | доступно, без KYC | OV-сертификат на имя «SignPath Foundation», ключ в их HSM, заявка ~1 неделя, GitHub Actions |
| Certum Open Source Code Signing | ~69 € | KYC, смарт-карта и ридер (доставка) | сертификат на имя разработчика; запасной вариант |
| Azure Artifact Signing (Trusted Signing) | ~$9,99/мес | физлица только США/Канада | облачный HSM |
| OV/EV коммерческих ЦС | $150–400+/год | KYC, аппаратный токен | EV больше не обходит SmartScreen сразу |
| Microsoft Store / MSIX | бесплатно | по сообщениям, верификация из РФ блокируется | MSIX переподписывает Microsoft |

В исследовании нет ссылок на источники и разные даты проверки (16.09 и
16.11.2026): цены и региональные ограничения перепроверить по первоисточникам
перед C1.

Решение-кандидат: **SignPath Foundation**.

## Что исследование упустило

1. **Порядок подписей.** Подпись обновлений Tauri (minisign, `.sig` в
   `latest.json`, ключ 82D55017631804B2 с паролем) считается по байтам файла,
   а Authenticode меняет EXE. Поэтому сначала SignPath подписывает установщик,
   затем пользователь локально выполняет `tauri signer sign` уже над
   подписанным файлом, затем `pnpm release:assets`. Обратный порядок сломает
   самообновление установленных копий.
2. **Сборка выпуска переезжает в CI.** SignPath подписывает артефакт, собранный
   GitHub Actions из публичного репозитория (проверка происхождения). Сейчас
   установщик выпуска собирается на ПК пользователя
   ([ранбук](../../runbooks/release.md)); CI «Quality gates (Windows)» уже
   собирает проект — нужен отдельный workflow выпуска с артефактом.
3. **Что именно подписывается.** Подпись установщика NSIS видна при запуске,
   но `glagol.exe` внутри останется неподписанным, если SignPath не умеет
   подписывать вложенные файлы NSIS (не подтверждено). Вариант — Tauri
   `bundle.windows.signCommand`, вызывающий подпись каждого бинарника во время
   сборки в CI; проверить поддержку со стороны SignPath.
4. **SmartScreen исчезнет не сразу.** Для OV предупреждение уходит по мере
   репутации. Открытый вопрос: копится ли репутация на общий сертификат
   «SignPath Foundation» (им подписаны многие проекты) — тогда быстро; при
   ~5 скачиваниях на выпуск собственная репутация копилась бы долго. Если
   установщик ставится без UAC (per-user), «Неизвестный издатель» в UAC может
   и не показываться — главный эффект именно SmartScreen и свойства файла.
5. **Условия SignPath:** OSI-лицензия (MIT — да), «без проприетарных
   компонентов». Глагол отдельно скачивает модели (Silero — CC BY-NC-SA, не
   OSI); в установщике их нет — объяснить в заявке. Нужны страница «Code
   signing policy» (README RU/EN: «Free code signing provided by SignPath.io,
   certificate by SignPath Foundation»), описание ролей (автор — коммиттер и
   апрувер), MFA, ручное одобрение каждого выпуска в портале SignPath.
6. **Риски:** отзыв сертификата при нарушении условий; токен SignPath — только
   в GitHub Secrets; подпись с меткой времени (RFC 3161), иначе после
   истечения сертификата подпись станет недействительной.

Запасной путь — Certum OSS (~69 €), если SignPath откажет.
Вне scope: Microsoft Store/MSIX, платные EV/OV.
