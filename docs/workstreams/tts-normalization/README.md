# Нормализация текста для озвучки: правила, словарь, ИИ

> План, согласованный 2026-11-20. Журнал — [log.md](log.md); очередь —
> [roadmap](../../roadmap.md); связанная серия — [tts-qwen](../tts-qwen/README.md).

## Context

Пользователь прослушал Qwen3-TTS и Silero на новостном тексте: обеим моделям
нужна нормализация — «980 млн» прозвучало как «девяносто восемдесят малерад».
Сейчас Глагол раскрывает только URL/email и часть сокращений
(`src-tauri/src/text/preprocessor.rs`), а числа переводит в слова Python-пакет
num2words внутри Silero-воркера — без падежей и без валют, и он недоступен
будущему нативному Qwen. Пользователь хочет: (1) нормализацию цифр и сокращений,
(2) свой словарь, который можно дополнять, (3) — в первую очередь для себя как
частного человека — ИИ-нормализацию «не сенситивных кусочков» по разрешению в
настройках.

Эксперимент 2026-11-20 (журнал серии tts-qwen): из новости вырезаются только
фрагменты с числами/валютами/латиницей (± 1 слово до, 2 после, ~10 % текста),
одним запросом уходят модели, ответы вставляются обратно. gemini-3.5-flash-lite
через RouterAI — 0,05 ₽ за новость, 2,4 с, одна типичная ошибка («восемьдесят
один целую»); gemini-3.5-flash — без ошибок при «думать поменьше», но 1,5–2,6 ₽.
Решение пользователя: flash-lite по умолчанию.

## Конвейер (порядок важен)

`текст → пробелы/URL/email (как сейчас) → словарь пользователя → [ИИ-фрагменты,
если включено] → правила (всё, что осталось) → адаптер движка (ударения «+»,
чанки)`. Словарь первым: он главнее всего. Правила последними: подбирают то, что
ИИ не вернул или вернул с ошибкой, и работают полностью офлайн.

## Шаги

### N1. Правила (Rust, офлайн, RU и EN)
Новый модуль `src-tauri/src/text/normalize/` (`ru.rs`, `en.rs`, `numbers.rs`):
- количественные числа словами: целые до триллионов, разделители тысяч
  (пробел, NBSP, точка/запятая в EN), отрицательные;
- **падеж** по контексту: предлоги (в, на, о, от, до, из, с, около, более,
  менее, свыше, к, по), глагол/существительное после числа, согласование рода
  с существительным (одна/один, две/два) — эвристики + таблица существительных
  из частых единиц; что не определить — именительный;
- дроби: «1,5 трлн» → «полтора триллиона», «81,3» → «восемьдесят одна целая
  три десятых» (с падежом), «0,5» → «ноль целых пять десятых»/«половина» по
  правилу;
- деньги и единицы: $, €, ₽, руб., долл., %, млн, млрд, трлн, тыс., км, кг,
  °C — с согласованием («$81,3 млрд» → «… миллиарда долларов»);
- годы и даты: «в 2026 году» → порядковое в нужном падеже, «20.11.2026»,
  «20 ноября 2026 г.», века римскими цифрами (XXI век);
- время «12:30», диапазоны «1–3», номера «№ 5», телефоны — по цифрам группами;
- латиница в русском тексте: известные аббревиатуры по буквам (IPO →
  ай-пи-о, USA → ю-эс-эй) из встроенной таблицы; остальное оставить движку;
- EN-текст: числа, деньги, проценты, даты по английским правилам;
- Silero перестаёт зависеть от num2words для этих случаев (num2words
  остаётся страховкой внутри воркера).
- Тесты: таблица ≥ 200 случаев RU и EN из новостей, включая пример
  пользователя; ничего не меняется в тексте без чисел/сокращений.

### N2. Словарь произношения пользователя
- Хранилище: append-only миграция SQLite `pronunciation_dictionary` (id,
  pattern, replacement, language ru/en/any, whole_word, case_sensitive,
  enabled, created_at). Входит в резервную копию.
- «Настройки» → «Озвучка» → «Словарь произношения» (свёрнут): таблица
  «Как написано → Как читать», добавить/изменить/удалить/выключить, поиск,
  импорт/экспорт CSV; подсказка про ударение «з+амок».
- Кнопка «Послушать» у строки — короткий синтез фразы с заменой.
- Встроенные стартовые записи (не в БД, отключаемые): IPO, AI/ИИ, CEO, SpaceX
  и т. п.
- Ударение: «+» передаётся Silero; для движков без поддержки — убирается.

### N3. ИИ-нормализация (по разрешению, офлайн-обещание сохраняется)
- По умолчанию **выключена**. «Настройки» → «Озвучка» → «Улучшенное чтение
  чисел через ИИ»: переключатель + явное предупреждение «в интернет уходят
  только короткие фрагменты с числами и сокращениями (≈ 10 % текста), сам
  документ — нет».
- Провайдер: OpenAI-совместимый адрес (`/chat/completions`) + модель + ключ —
  пресеты RouterAI (`https://routerai.ru/api/v1`, `google/gemini-3.5-flash-lite`)
  и AITunnel (`https://api.aitunnel.ru/v1`, `gemini-3.5-flash-lite`), «свой
  адрес»; ключ — отдельный слот keyring; кнопка «Проверить».
- Фрагменты: как в эксперименте (числа/валюты/латиница ± контекст, в пределах
  предложения, слияние пересечений); пакет до ~40 фрагментов на запрос;
  temperature 0; ответ — JSON-массив той же длины.
- Проверка ответа: длина массива; в каждом ответе нет цифр и латиницы; слова
  без чисел сохранены (сравнение «хвостов» фрагмента); удаление
  комбинирующих ударений (U+0301); любой сбой фрагмента → правила N1.
- Таймаут 20 с на запрос, не более 3 параллельных; при ошибке сети документ
  озвучивается на правилах с тостом «ИИ недоступен — числа прочитаны
  стандартно».
- Кэш по хешу фрагмента в памяти на время работы (повторы в новостях).
- Журнал: только счётчики и время, без фрагментов и ответов; ключ — только в
  keyring.
- Опция «Предпросмотр»: кнопка «Как прочитается» на экране «Озвучить»
  показывает нормализованный текст до синтеза (и правила, и ИИ).

### N4. Документы и проверка
USER_GUIDE RU/EN (разделы о чтении чисел, словаре, ИИ), README обе части,
CHANGELOG, SECURITY (что уходит в сеть при ИИ-нормализации), CLAUDE.md
(инвариант: ИИ-нормализация только по разрешению, фрагменты, без журналов).
Ручная проверка на ПК: новость пользователя на Silero и (после tts-qwen)
на Qwen; словарь; ИИ вкл/выкл; отключённая сеть.

## Риски
Падежи правилами — не 100 %; ИИ может исказить фрагмент (валидация +
откат на правила); стоимость — копейки, но показывать примерную оценку.
