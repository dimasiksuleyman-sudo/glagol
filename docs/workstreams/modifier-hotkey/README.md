# Диктовка по удержанию только модификаторов (Ctrl+Win)

Цель: push-to-talk по удержанию одних модификаторов, прежде всего Ctrl+Win,
без третьей клавиши.
Основание: сообщение пользователя 2026-11-10 — «Можно ли в принципе выбирать
Ctrl+Win?… До нашей программы я использовал Wispr Flow, и там это работает
отлично и для многих привычно»; просьба записать в TODO.

Сейчас (0.6.5): хоткей регистрируется через tauri-plugin-global-shortcut →
global-hotkey 0.8.0 → RegisterHotKey, которому нужен код обычной клавиши;
модификаторы-only не регистрируются. Win (Super) + клавиша принимается
(ручной ввод `Ctrl+Super+Space`), но редактор её часто не ловит, и многие
Ctrl+Win-сочетания заняты Windows.

Направление (согласовать перед началом):
- низкоуровневый хук клавиатуры (WH_KEYBOARD_LL) в отдельном потоке, только
  состояние модификаторов, без записи нажатий и без журнала клавиш;
- начало — когда удерживаются ровно выбранные модификаторы (с порогом против
  случайных сочетаний), конец — отпускание; отмена, если во время удержания
  нажата другая клавиша (это обычное сочетание, а не диктовка);
- не дать Windows открыть «Пуск» при отпускании Win (подавить/подменить
  событие), проверить на Windows 10 и 11;
- режим в настройках рядом с горячей клавишей; прежний RegisterHotKey остаётся
  вариантом по умолчанию;
- риски: реакция антивирусов на хук, задержки обработчика (хук должен
  возвращаться мгновенно), безопасность (никаких данных о нажатиях наружу).
Вне scope: произвольные одиночные клавиши без модификаторов.
