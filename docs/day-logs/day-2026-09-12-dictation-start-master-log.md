# Glagol — 2026-09-12 — запуск микрофона и сигнал готовности

## Задача и принятое решение

На Windows 11 пилюля показывала запись примерно на секунду раньше фактического
начала захвата. Если говорить по этому сигналу, начало фразы терялось.

В коде подтверждены три преждевременных сигнала: окно и recording-иконка трея
включались при нажатии хоткея, pipeline отправлял Recording до ожидания Start,
а успешный Start означал возврат команды запуска потока, а не приход аудио.

Пользователь выбрал **«Подготовка, затем сигнал записи»**. Постоянно открытый
микрофон и предварительный буфер не вводились. Речь до готовности устройства
восстановить невозможно; пользовательские инструкции прямо описывают это.

## Изменения

- В контракт событий Rust/TypeScript добавлено Starting. Пилюля показывает
  «Подготовка микрофона…», затем красную точку и полоски после готовности.
- Recorder подтверждает Start после сохранения первого непустого аудиопакета.
  Тихий пакет тоже подтверждает готовность: ожидания ненулевого RMS нет.
- Ожидание первых данных ограничено пятью секундами после открытия потока.
  Ошибка, отмена и завершение освобождают устройство и ожидающий Start.
- Отпускание хоткея во время подготовки отменяет попытку без STT. Pipeline
  дожидается остановки recorder перед разрешением следующей сессии.
- Трей использует тот же сигнал готовности. Новый Starting сбрасывает старый
  таймер скрытия пилюли и уровень звука.
- Диагностическая строка `dictation capture ready` содержит время запуска и
  размер первого пакета. Аудио, ключи и текст речи в лог не добавлялись.
- Синхронно обновлены RU/EN README и USER_GUIDE, CHANGELOG/Unreleased и схема
  потока в PROJECT_STRUCTURE. Схема БД, зависимости и версия не менялись.

Добавлено 8 тестов, удалено 0: **353 всего, 352 passed, 1 ignored**.
Три ранее игнорируемых doc-теста также остаются ignored.

- `startup_timeout_releases_device_and_allows_retry`

Существующие recorder-тесты адаптированы к ожиданию первого пакета; обновлены

Тесты отмены и таймаута проверяют фактический вызов остановки источника.

Negative regression cycle выполнен: временный возврат раннего подтверждения
Start и раннего Recording вызвал два ожидаемых падения тестов готовности.
После восстановления исправления полный набор прошёл.

## Сборка, установка и проверка пользователем

При сборке вновь проявилась известная проблема Pdfium: новый OUT_DIR и
недоступность загрузки приводят к отсутствию compile-time PDFIUM_LIBRARY_PATH.
Использован путь к реальной локальной DLL из resources; исходники PDF не менялись.
Для загрузки test-зависимостей и официального NSIS понадобился разрешённый
доступ вне сетевой песочницы. Tauri проверил хеши инструментов упаковки.

Собран тестовый NSIS-установщик 0.2.1. После удаления старой версии пользователь
попросил установить новую. Установка завершилась с кодом 0, приложение запущено.
Проверено соответствие установленного EXE сборке: отличие только в штатной
метке Tauri UNK → NSS; после нормализации этой метки в памяти SHA256 совпали.

Первая проверка после установки: точка появляется, полоски неподвижны,
после отпускания пилюля исчезает. Процесс унаследовал RUST_LOG=warn от окружения
запуска; для диагностики его перезапустили с обычным release-фильтром проекта.
Свежая попытка показала готовность через 622 мс, 2598 мс записанного аудио,
RMS=0.0 и отбрасывание как Silent. Нулевые записи присутствовали и в логах
старой версии до изменения кода.

Windows Core Audio подтвердил **Muted=True** у системного микрофона при уровне
входа 32%. Отключение снято, громкость сохранена; повторное чтение — Muted=False.
После перезагрузки пользователь подтвердил: **«Теперь диктовка работает как надо,
перезагрузка помогла»**. Раздельного измерения влияния снятия mute и перезагрузки
не проводилось; приписывать восстановление звука только одному действию нельзя.
